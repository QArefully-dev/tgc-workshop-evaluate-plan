# Fresh v3 grader instructions

Input gate: host-verified `run-manifest.json` + complete frozen `plan-grading-template.md`, `rubric-v3.json`, `report-schema.json`, prompt, ticket, candidate and source snapshot. Read complete package. Missing/mismatched content -> stop, report invalid run; never reconstruct rubric from memory/main URL. Ignore prior grades; host excludes them. Calibration expected decisions never grader input.

1. Read task/ticket and candidate. Resolve source-grounded fixture assumptions, structural bounds, compatibility, policy caps, quantity and pricing independently.
2. Identify explicit assertion instances for each ID. Cite candidate location/phrase and scenario. Missing assertion -> `missing`, empty assertions, precise absence evidence. Incorrect assertion/oracle -> `incorrect`, cite wrong claim. Evaluate prerequisite statuses separately.
3. For every present instance, fill exact prerequisite IDs from manifest with candidate/source evidence. Product failure in behavior being tested does not invalidate setup. Reachable handling-guidance assertion gets credit even when product missing guidance. Invalid authored data blocks dependent assertion; include clamp/cap reasoning. Independent alternative assertion may satisfy same ID.
4. `met` requires at least one correct planned assertion with all prerequisites `satisfied`. Correct assertion with only invalid/unknown prerequisites -> `blocked`. No blanket scenario zero. S01 materials only, S02 ratios only, S08 structure only; S05 correct independent arithmetic without immaterial explanation accepted regardless of separate recipe reachability.
5. Fill artifact/process compliance rules. Process claims in candidate insufficient; host trace/diff evidence required, absent -> `unknown`. Efficiency from host logs only, otherwise unknown. No quality deductions for compliance/efficiency.
6. Return raw JSON matching schema, exact 41 weighted results, all compliance IDs, up to three improvements. Copy manifest input hashes/version/run ID exactly. No totals, percentages, normalization or final score: host validator calculates.

Result shape: `id`, integer `weight`, `status`, `evidence`, `assertions`. Assertion shape: unique local `assertion_id`, `scenario`, `evidence`, `expectation` (`required_behavior` or `product_defect_expected`), `prerequisites`. Each prerequisite: `id`, `status` (`satisfied`, `invalid_authored_setup`, `unknown`), nonempty `evidence`. S IDs have empty prerequisite arrays but still need cited assertion/planning evidence when present.

Compliance rule IDs: `english`, `word_limit`, `headings`, `scenario_limit`, `output_path`, `static_reads_only`, `relevant_code_and_tests_read`, `no_external_access`, `no_browser_or_app`, `no_test_execution`, `no_install_or_reset`, `no_subagents`, `no_user_questions`, `authorized_edits_only`. Status `met`, `violated`, `unknown`; evidence required. First five artifact-only; relevant reads separate process completeness; other process IDs serious for eligibility. Any serious violated -> ineligible; all serious met -> eligible; otherwise unknown.

Efficiency: `duration_seconds` nonnegative number or `unknown`; `tokens` nonnegative integer or `unknown`; `cost` amount + currency string or `unknown`; `evidence` host-log citation or explicit unavailable statement. Preserve unknowns; do not invent configuration/trace/browser facts.
